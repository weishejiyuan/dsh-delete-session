# 5. 不提供撤销窗口

日期：2026-11-19
状态：已接受

## 背景

用户明确要求「永久删除」，不接受软删除/回收站语义。是否在删除后提供短暂撤销窗口，是设计时的一个选项。

## 决策

不提供撤销窗口。删除成功后立即 `notify()` 一个 toast，文案为「会话已永久删除」，无「撤销」动作。

## 理由

- 「永久删除」的语义就是不可恢复。加撤销窗口会模糊这个边界，用户会误以为文件还在某处。
- DSH 没有会话级回收站；真正的撤销需要把目录移走再保留引用，等于多一套生命周期要维护。
- 二次确认框已经承担了防误删职责；撤销窗口会稀释确认框的注意力。

## 后果

- 误删只能从备份/卷影副本/文件系统恢复，DSH 不提供内置路径。
- 确认框的文案必须写清楚「此操作不可撤销」，不能只写「确定删除吗」。
- 若将来用户反馈需要撤销，应作为独立 ADR 评估，而不是在本插件里偷偷加一个隐藏备份。
